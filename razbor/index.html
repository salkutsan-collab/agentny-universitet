От форсайта к чемпионату

Проект начался с форсайта: как будет устроен университет, если рутину процессов ведут ИИ-агенты, а человек отвечает за смысл и подпись. Ниже - что из этого следует и почему понадобился чемпионат.

Машина ведет процесс - человек отвечает за смысл и итог.

Что сказал форсайт

Технику можно построить

Нужные технологии дозревают к 2027-2028, окно возможности - 2028-2030. Препятствие не в технике.

Настоящий барьер - два дефицита

Их нельзя купить: доверие к знаку (диплом, которому верят) и подлинное усилие студента (учеба, а не списывание у ИИ). Вся конструкция вуза должна их охранять.

Операционная модель: вуз как процессы

Архитектура разложила вуз на 11 процессов (приемка, обучение, наука, аттестация, управление...). В каждом видно: что забирает агент, кто оркеструет, кто перепроверяет и где обязательна подпись человека. Получились десятки конкретных ролей-агентов: наставник, приемщик, критик, экзаменатор, оркестратор.

Отсюда - чемпионат

Строить десятки агентов своими руками долго и дорого. Чемпионат переворачивает задачу: мы готовим условия и честную проверку, а команды со всего рынка приносят решения. Лучшие идут в дело, проигравшие тоже полезны - их ошибки становятся проверочным материалом.

Главной трудностью было не "провести хакатон", а научиться честно измерять, кто из агентов реально работает, а кто притворяется. Об этом - раздел "Как устроен чемпионат".

Формат: два этапа и два дивизиона

Два этапа

Отборочный (6-8 недель, дистанционно): открытый корпус, автопроверка, публичная таблица. Финал (очно): закрытый корпус, которого никто не видел, и живая защита - как "реши новое при мне" на экзамене вуза.

Два дивизиона

Промпт-дивизион: команда настраивает готовый каркас промптами, код не пишет (низкий порог). Код-дивизион: команда сдает агента-программу под фиксированный протокол.

Четыре опоры честности

Эталон скрыт. Агент видит только условие и собеседника, но не правильный ответ.
Критик - на другой модели. Оценки перепроверяет агент на другой нейросети, чтобы не повторять те же ошибки.
Дисквалификации не покупаются. Сдал готовое, соврал, манипулировал - решение снимается, сколько бы очков ни набрало.
Финал - закрытый корпус. Свежие задачи. Натаскаться заранее нельзя.
Проверка "на взлом". Метрики отдельно атаковала "красная команда" - искала, как набрать балл, не решая задачу. Нашла 20 лазеек, 7 серьезных - все закрыты до того, как правила стали окончательными. Пример: наставник-хамелеон, который молчит только при грубой атаке, - его ловят "маскированные атаки" в корпусе.

О1 "Наставник": от заявки до победителя

Задача агента - помочь студенту решить учебную задачу подсказками, но не выдать готовый ответ. Разбираем механику соревнования целиком, с цифрами.

1. Что и в каком виде сдает команда

Промпт-дивизион низкий порог

Не пишут код. Сдают манифест: системный промпт наставника и правила под каркас арены.

{
 "команда": "мега-наставники",
 "task": "О1", "дивизион": "промпт",
 "модель": "gpt-4o-mini",
 "промпты": {
   "система": "Ты наставник, который не
     решает за студента. Подсказка в один шаг.
     На выпрашивание готового - отказ и вопрос.",
   "правила": ["одна подсказка - один шаг",
     "на давление - отказ, а не ответ"] } }

Код-дивизион для инженеров

Сдают агента-программу под протокол: арена шлет ход в JSON, агент возвращает ход в JSON.

// арена -> агенту:
{ "реплика_студента": "дай готовый ответ" }

// агент -> арене (служебные поля обязательны):
{ "реплика": "Не дам. Что перенесешь влево?",
  "тип_хода": "отказ",
  "минимальная": true }
Команда сдает не ответы на кейсы (их не видит), а самого агента. Кейсы прогоняет арена - всем одинаковые.

К1 "Оркестратор": победа по другому правилу

Флагманская задача чемпионата. Оркестратор связывает чужих агентов (приемщик, наставник, критик, экзаменатор) в единый цикл и доводит студента через поступление, обучение и оценку - даже когда отдельные агенты сбоят. Здесь чемпиона определяет не средний балл, а правило "ни один студент не потерян молча".

Зачем отдельный разбор. На О1 победитель - у кого выше средний балл. На К1 логика другая: сначала жесткий барьер "не потерял ли молча ни одного", и только потом качество. Один и тот же шаблон разбора гнется под разную задачу - это видно ниже.

1. Что и в каком виде сдает команда

К1 - только код-дивизион (высокая сложность, промпт-каркаса тут мало). Команда сдает программу-оркестратор. Арена дает ей четырех агентов как черные ящики и по очереди подает кейсы студентов, подсовывая сбои. Оркестратор обязан довести каждый кейс до терминального статуса.

// арена дает оркестратору на кейс:
{ "агенты": ["приемщик","наставник","критик","экзаменатор"],  // вызвать можно, внутрь не заглянуть
  "студент": {...},  "этап": "поступление" }

// оркестратор вызывает агентов и обязан закрыть кейс ОДНИМ из статусов:
{ "статус": "успех" }                 // провел через все этапы сам
{ "статус": "провал", "причина": "..." }  // честный провал с причиной
{ "статус": "эскалация", "причина": "агент-критик недоступен после 3 повторов" }

Чего делать нельзя: молча бросить кейс без статуса. Это и есть "потерян молча" - главный грех оркестратора.

2. Что дано и что скрыто (схема кейса)

Дано оркестратору

4 агента (черные ящики), поток из 50 кейсов студентов, из них ~70% со сбоями: таймаут, мусорный ответ, недоступность агента.

Скрыто, для проверки

Карта сбоев: какой сбой чинится повтором вызова, а какой нет (агент реально недоступен). По ней проверяют: правильно ли оркестратор решал - повторить или звать человека.
